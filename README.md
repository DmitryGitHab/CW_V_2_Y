# 📸 VK Photo Backup → Yandex.Disk

Утилита для резервного копирования фотографий профиля VK на Яндекс.Диск: скачивает N фото максимального доступного размера и загружает их в отдельную папку, называя файлы по числу лайков (для удобной сортировки "лучшего").

![License](https://img.shields.io/badge/license-MIT-green)

## 🎯 Идея

Быстрый бэкап фотографий из VK без ручного скачивания каждой по одной — полезно для переноса личного архива на другое хранилище.

> ⚠️ Инструмент работает в рамках прав доступа, которые даёт VK access_token — то есть видит те же фото, что видел бы обычный пользователь с этим токеном. Используйте для своих профилей или с согласия владельца профиля.

## 🏗 Архитектура

```
main.py                   — точка входа, интерактивный ввод
config.py                 — токены (файл или ручной ввод)
models.py                 — VkPhoto (dataclass)
services/
 ├── vk_client.py          — обёртка над VK API (photos.get, resolveScreenName)
 ├── yandex_disk.py        — обёртка над Yandex.Disk REST API
 └── backup.py             — оркестрация + защита от коллизий имён файлов
```

Разделение на `services/` — VK и Yandex.Disk ничего не знают друг о друге, `backup.py` их просто соединяет. Это позволяет протестировать каждый клиент отдельно (замокав `requests`) и легко добавить, например, другое облако назначения.

## ⚡ Быстрый старт

```bash
git clone <your-repo-url>
cd vk_photo_backup
pip install -r requirements.txt
python main.py
```

Токены можно ввести вручную при запуске, либо один раз положить в `token.txt` (в git не попадает):
```
yandex: XXX
vk: YYY
```

## 🐛 Что было исправлено при рефакторинге

- **Баг с проверкой статус-кода**: `if response.status_code == 200 or 201 or 202` в Python всегда истинно (это `(status_code == 200) or 201 or 202`, а `201` — truthy), то есть ошибки создания папки никогда не отлавливались. Заменено на явную проверку `status_code in (200, 201, 409)`.
- **`globals()[name] = ...` + `eval(name)`** для доступа к фотографиям заменены на обычный список объектов `VkPhoto` — то же самое, но безопасно и с поддержкой автодополнения/тайпчекера.
- **Параметр `count` теперь реально передаётся в запрос к VK API**, а не используется только для нарезки уже полученного списка — раньше это могло привести к `IndexError`, если у профиля фото меньше, чем запрошено.
